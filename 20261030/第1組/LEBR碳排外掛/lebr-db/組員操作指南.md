# LEBR 碳排外掛：組員操作指南

這份指南寫給之後會用到、或繼續開發這個外掛的組員。先看自己的角色那一節就好。

| 你的角色 | 看哪一節 |
|---|---|
| 在 Revit 建模、要算碳排的人 | 一、建模者 |
| 維護 LEBR 資料庫（係數、參數表） | 二、資料庫負責人 |
| 改外掛程式（數量擷取、計算引擎、視窗） | 三、外掛開發者 |
| 做網頁視覺化 | 四、網頁組 |

所有人都要遵守最後的「五、共同規則」。

---

## 一、建模者：在 Revit 算碳排

### 第一次使用

> 圖文版的步驟在 **`先看這個_快速開始.md`**，建模者看那份就夠了。

1. 關掉 Revit，雙擊交接包最上層的 **安裝外掛.bat**。它會自動找出電腦上的 Revit 2024～2027，裝好對應的版本（Revit 2024 版可以編譯，但還沒實測，有問題請回報）。

    從 GitHub 原始碼開始的人，可以到 [GitHub 下載頁](https://github.com/017-YiChing/2026_NCKU_BIM_Course_Group-1/releases/tag/lebr-midterm-20261102) 下載已編譯好的「外掛交接包」；要自己編譯，則先裝 .NET SDK 10，再在 `lebr-db` 資料夾執行（Revit 2024 要加 `-RevitVersion 2024`）：

    ```
    powershell -ExecutionPolicy Bypass -File revit-addin/install.ps1
    ```

2. 開 Revit。跳出「無法驗證此增益集的發佈者」時，選 **永遠載入**。
3. 功能區出現 **LEBR** 頁籤，裡面有「專案設定」、「開始計算」兩個大按鈕，以及「代號 JSON」、「使用說明」兩個小按鈕。

### 每個新專案做一次

- 按 **LEBR → 專案設定**，第一次會自動建立 LEBR 參數，已經有的不會重複建立。填完按「儲存」。
- 或者按 **LEBR → 代號 JSON → 套用代號**，選別人匯出的代號檔：參數、類型代號、專案資訊、不計入元件一次填好。自己填好的模型可用「匯出代號」分享給組員（依類型名稱對應，名稱要相同）。

### 專案設定（建議用這個填專案資訊）

1. 按 **LEBR → 專案設定**，表單會讀取目前專案資訊的 `LEBR_*` 參數。
2. **A 主結構（基準案同設計案）**：
   - A-1（依結構計算書之數值填寫）：用途係數 I（下拉：第一、二類 1.5、第三類 1.25、第四類 1.0）、SaD、Fu、L、D0、Rs（下拉 0.95／1.00，預設 0.95）。
   - A-2（僅設計案）：CSER、覆寫 Sp、覆寫 F。
   - 「使用估算」：勾選後 A 區鎖定。按「開啟估算」可選擇每個品類的附錄一材料，按「計算」查看結果，按「計算並儲存」寫入專案的 `LEBR_CFs` 與 `LEBR_EstimateJson`，CFs 會作為設計案主結構值（不再計算 Sp、F）。取消勾選會清除估算結果。
     之後按「開始計算」，外掛會依目前模型重新讀取數量、沿用估算紀錄裡的材料選擇重算（`CalculateCommand.RefreshEstimate`、`csharp/Estimate/EstimateRefresh.cs`），結果只用在這次計算與結果 JSON，不寫回模型；模型新增了沒選過材料的品類（例如新增鋼筋）時沿用已儲存的估算並提醒。
3. **B 非主結構**：覆寫 AFu，只在需要時勾選。
4. **C 優惠係數（LL）**：耐久設計、高品質施工各擇一，可以兩組同時選。合計超過 0.08 以 0.08 計。項目 1、2 只適用 RC（SRC 不能選）。需附證明文件，未附則為 0。
5. **覆寫欄位**（S、Sp、F、AFu）平時收合，勾選後才會顯示；取消勾選會清空已填的值。S 同步套用到基準案；Sp、F 只影響設計案。
6. **CSER**：只有構造為 RC 或 SRC 時可勾選；未勾選寫入 0，勾選後可輸入任意數值。
7. 按「儲存」寫回專案資訊。`LEBR_LL` 寫入合計值，`LEBR_LL_Durable`、`LEBR_LL_Quality` 記錄所選項目，下次開啟時會還原選單。
8. **必填檢查**：I、SaD、Fu、L、D0 任一未填（且未勾選「使用估算」）時，「儲存」按鈕會停用，檢查列會列出缺少的項目，I 未選時下拉框線為紅色。

### 建模時要填的參數

**類型參數**（在「編輯類型」裡填，同一類型填一次就好）：

| 品類 | 參數 | 填什麼 |
|---|---|---|
| 外牆 | `LEBR_Code` | 外裝代號（`OW-…`） |
| 外牆 | `LEBR_Code_Body` | 外牆本體代號（`CW-…`），例如 RC 外牆填 `CW-00` |
| 內隔間牆 | `LEBR_Code` | `IW-…`，**不用寫建築類別**，外掛會自己補 |
| 窗 | `LEBR_Code` | `W-…` |
| 帷幕嵌板 | `LEBR_Code` | 透光填 `CWW-…`，不透光填 `CW-…` |
| 地坪（樓板面層） | `LEBR_Code` | 室內 `F-…`、戶外 `P-…`，**不用寫建築類別** |

**不計入的元件**：勾選元件的 `LEBR_Exclude`。例如樓梯間牆、電梯間牆、住宅分戶牆、教室隔間牆、停車場地坪、屋頂板。

**專案資訊**（管理 → 專案資訊）：

| 參數 | 填法 |
|---|---|
| `LEBR_WearClass` | `H` 高耗損（商場、旅館、醫院）／`M` 中耗損（學校、出租辦公）／`L` 低耗損（住宅、自用辦公） |
| `LEBR_Structure` | `RC`、`SRC`、`S`、`light_steel`、`wood` |
| `LEBR_UseType` | `residential`（住宿、旅館、醫院）／`factory`（廠房）／`other`（其他） |
| `LEBR_I`、`LEBR_SaD`、`LEBR_Fu` | 結構計算書的地震參數 |
| `LEBR_L`、`LEBR_D0` | 活載重、額外靜載重（kgf/m²） |
| `LEBR_Rs` | 不需動力分析填 0.95，否則填 1.0 |
| `LEBR_CSER` | 低碳混凝土；未勾選寫入 0，可用「專案設定」填（RC 或 SRC 才可勾選） |
| `LEBR_LL`、`LEBR_LL_Durable`、`LEBR_LL_Quality` | 延壽優惠（表 5-2）合計與所選項目，由「專案設定」寫入，不需手動填 |
| `LEBR_AFu`、`LEBR_S`、`LEBR_Sp`、`LEBR_F` 等 | **選填**。模型算錯時才用來覆寫，例如模型少畫一層樓板 |

### 常用代號速查

完整清單見 `draft/LEBR資料庫_核對用.xlsx` 或 `README.md`「構件編號規則」。帶「基準」的是手冊的一般做法，選其他做法才會有減碳量。

| 代號 | 構造 |
|---|---|
| `OW-01` | RC 外牆貼磁磚（基準） |
| `OW-02` | RC 外牆乾式鋼件掛石材 |
| `OW-03` | RC 外牆塗料外裝 |
| `CW-00` | 傳統 15cm RC 外牆（外牆本體基準） |
| `W-G01-AL`／`W-G01-PVC` | 6mm 普通玻璃，鋁框（基準）／塑鋼框 |
| `W-G14-AL` | 6+6mm Low-E 玻璃，鋁框 |
| `CWW-G14-ALPVC` | 6+6mm Low-E 玻璃，帷幕牆鋁框 |
| `IW-01` | 磚牆雙面粉刷（基準） |
| `IW-02`／`IW-03` | 輕質灌漿牆／輕隔間牆（矽酸鈣板） |
| `F-G01` | 貼磁磚地坪（一般地坪基準） |
| `F-G02`／`F-G06` | 整體粉光地坪／PU、Epoxy 等 |
| `F-W01` | 木作地坪基準（角材墊高平鋪超耐磨地板） |
| `P-RC01`／`P-GR01` | 戶外 RC 基礎貼磁磚（基準）／碎石基礎乾砌植草磚（基準） |

### 算碳排

1. 模型建好後，按 **LEBR → 開始計算**。
2. **計算前檢查**會列出：
    - **未對應**：沒填代號的元件，代表會少算。
    - **缺少**：沒填的專案參數。缺結構參數時，主結構不會計算。
    - **說明**：外掛算出的樓層數、樓地板面積、Sp、F，請確認合不合理。
3. 可以先按「取消」去補，或直接按「開始計算」。
4. **結果視窗**有五個分頁：四個階段、七類構件、構件明細（雙擊一列可在模型中選取元件）、主結構、提醒與未對應。
5. 按 **匯出結果 JSON**，把檔案交給網頁組。
6. 模型修改後，**再按一次「開始計算」**。外掛不會自己重算。

> 結果視窗上方有黃色提醒時，代表資料庫還沒核對完，或有必要資料沒填。這時的等級只能當參考。

## 二、資料庫負責人：維護 LEBR 資料庫

資料庫只存手冊的數字（係數、參數表、公式常數），不存計算方法。外掛只讀 `dist/lebr_2025.json`。

### 修正一個數字

1. **不要直接改 CSV 或 JSON。** 打開 `corrections.csv`，新增一列：資料庫、編號、欄位、原值、修正值、依據、決定者、日期。欄位寫法見 `README.md`。用 Excel 編輯時，存成「CSV UTF-8」。
2. 在 `lebr-db` 資料夾執行：

    ```
    python -I scripts/build_json.py .
    ```

    原值對不上時，程式會停下來報錯，照錯誤訊息更新原值即可。

3. 執行測試，確認還是「全部通過」：

    ```
    dotnet run --project csharp/LebrDatabase.Tests -f net8.0
    ```

4. 把新的 `dist/lebr_2025.json` 交給外掛開發者，請他重新安裝外掛（見「五、共同規則」第 2 點）。

### 核對完成時

1. 在 `README.md` 最後的「核對紀錄」寫上日期、核對人、範圍。
2. 把 `scripts/build_json.py` 裡的 `REVIEW_STATUS` 改成 `"reviewed"`，再執行一次 `build_json.py`。結果視窗的「草稿」提醒就會消失。

### 手冊改版時

1. 用新版 PDF 重抽表格：

    ```
    python -I scripts/extract_lebr_tables.py "<新版手冊PDF>" draft
    ```

2. 重做核對用 Excel（會覆蓋舊檔，請先備份已填的那份）：

    ```
    python -I scripts/build_review_xlsx.py "<新版手冊PDF>" draft
    ```

3. 人工核對；參數表 `source/parameters_2025.json` 要另外對照手冊更新。
4. 執行 `build_json.py`。如果 `corrections.csv` 裡的修正對不上新資料，程式會報錯，逐筆確認新版是否已經修正。
5. 欄位結構有改時，把 `build_json.py` 的 `SCHEMA_VERSION` 主版號加一，並通知外掛開發者。

## 三、外掛開發者：修改外掛程式

### 開發環境

- Windows、Revit 2027、.NET SDK 10。
- 不需要開 Revit 就能跑測試和預覽視窗。

### 修改流程

1. 改程式：
    - 計算邏輯在 `csharp/LebrEngine.cs`。
    - 讀資料庫在 `csharp/LebrDatabase.cs`。
    - Revit 端在 `revit-addin/`：`Revit/` 是數量擷取與建立參數，`UI/` 是視窗。
2. 執行測試（計算引擎有用手冊附錄三自動驗證）：

    ```
    dotnet run --project csharp/LebrDatabase.Tests -f net8.0
    ```

3. 只改視窗時，可以不開 Revit 直接看：

    ```
    dotnet run --project revit-addin/Preview -- . shots --interactive
    ```

4. 安裝到 Revit。**Revit 開著時舊版 DLL 會被鎖住**，請換一個新資料夾名稱安裝，再重開 Revit：

    ```
    powershell -ExecutionPolicy Bypass -File revit-addin/install.ps1 -Folder LebrCarbon_5
    ```

5. 在 Revit 用**小模型**測試。Snowdon Towers 範例檔太大，在部分電腦上會卡死。

### 寫程式時注意

- `LebrDatabase.cs`、`LebrEngine.cs` 要維持 C# 7.3 寫法，Revit 2022～2024（.NET Framework 4.8）才能編譯。
- Revit SDK 的全域 using 會和 WPF 撞名（`Visibility`、`Color`、`Point`），要加 `using X = System.Windows...;` 別名。
- 公式常數不要寫死在程式裡，用 `db.Parameters.Constant("structure_C", "base")` 讀取。
- PowerShell 腳本含中文時，要存成 **UTF-8 with BOM**。

### 兩份交接格式（改了要通知其他人）

| 格式 | 範例檔 | 誰產生 → 誰使用 |
|---|---|---|
| 數量格式 | `samples/appendix3_quantities.json` | 模型擷取（或手動）→ 計算引擎 |
| 結果格式 | `samples/sample_result.json` | 計算引擎 → 網頁 |

結果格式的範例可以重新產生：

```
dotnet run --project revit-addin/Preview -- . samples --export
```

## 四、網頁組：做視覺化

- **你只需要讀結果 JSON**，不需要自己算碳排，也不用碰 Revit。
- 開發時用 `samples/sample_result.json`（手冊附錄三：1+ 級、CFR 20.51%）。正式資料由建模者在結果視窗按「匯出結果 JSON」提供。
- 結果視窗的「在圖台開啟」會把結果 JSON 以 gzip ＋ base64url 放在圖台網址的 `#d=` 後面，用預設瀏覽器開啟（`csharp/DashboardLink.cs`）。圖台用 `decodeData()` 讀 `#d=`。網址讀外掛資料夾的 `dashboard_url.txt`，沒有就用預設圖台；網址超過 30,000 字元時改存暫存 JSON、開空白圖台。

| 欄位 | 內容 |
|---|---|
| `project` | 數量來源、地上／地下樓地板面積、樓層數、建築類別、LL |
| `result` | `grade` 等級、`CFR` 減碳率（**小數**，0.2051 = 20.51%）、`ECI`／`ECIs` 碳排密度、`EEC`／`EECc`、`TEC`、`complete` 是否完整 |
| `grade_scale` | 1+～7 級的 ECI 刻度，可畫等級尺 |
| `by_stage` | 四個階段，設計案與基準案的碳排 |
| `by_component` | 七類構件，設計案與基準案的碳排 |
| `items` | 每個構件代號的面積與碳排明細 |
| `structure` | 主結構（欄位依《主結構 BIM 數量法｜結果 JSON 輸出規格》第 2-1 節）：`method` 是 `standard`（式 1～7）、`bim_quantity`（採結構碳排估算值 `LEBR_CFs`）或 `none`；`design_CFs`、`baseline_CFsc`、`intensity`（CFs ÷ AFu）、`AFu`、`underground_CFs`；`standard` 內是式 4、式 1 的參數與中間值（I、SaD、Fu、L、D0、Rs、BH、Sp、F、Rn、LCCR、C、W 與 `baseline_` 開頭的基準案值），算不出來的為 `null`；`bim` 是 BIM 數量法明細（`quantities` 各品類 × 樓層的混凝土、鋼筋量，`factors` 附錄一係數，`model_description`、`levels`、`totals`），只有 `method` 是 `bim_quantity` 且估算視窗用新版按過「計算並儲存」時才有值，其他情況為 `null` |
| `inputs` | 計算用的輸入：`building`（AFu、AFb、S、Sb、BH、Sp、F）與 `project`（建築類別、構造、I、SaD、Fu、L、D0、Rs、CSER、LL、EBF、`structure_CFs` 等），可做輸入參數面板 |
| `unmapped`、`issues` | 未對應元件與計算提醒 |
| `database.review_status` | 是 `draft` 時，畫面要標示「草稿，僅供參考」 |

單位都是 kgCO2e，ECI 是 kgCO2e/m²。建議至少做三張圖：等級尺、四個階段長條圖、七類構件組成。

## 五、共同規則

1. **資料庫只有一個來源**：`dist/lebr_2025.json`。外掛安裝資料夾裡的那份只是複本。
2. **資料庫更新後，外掛要重新安裝**（執行 `install.ps1`），新的 JSON 才會複製過去。
3. **結果不等於標章認證。** 送審仍要評定專業機構審查；資料庫核對完成前都是草稿。
4. **改了交接格式、代號規則或參數名稱，要先在群組說**。已經填過代號的模型可能要重填。
5. 每次修改後都要跑一次測試，確認「全部通過」再交出去。
