## 環境需求

- Windows、**Revit 2027**（完整實測過）。專案檔也有 2024～2026 的編譯設定；**課堂用的 Revit 2024 已有組員實際跑過「開始計算」（2026-10-25），但「代號 JSON」按鈕還沒在 2024 上試過**，安裝時加 `-RevitVersion 2024`
- **.NET SDK 10**（編譯外掛與跑測試）
- Python 3 + `pymupdf`、`openpyxl`：只有重抽 PDF 或重做核對 Excel 才需要
- 手冊 PDF：《2025低碳(低蘊含碳)建築評估手冊(上網版).pdf》，內政部建築研究所網站可下載

## 怎麼跑起來

以下指令都在 `lebr-db` 資料夾執行。

1. 跑自動測試，確認環境沒問題（應顯示「全部通過」）：

    ```
    dotnet run --project csharp/LebrDatabase.Tests -f net8.0
    ```

2. 關掉 Revit，編譯並安裝外掛：

    ```
    powershell -ExecutionPolicy Bypass -File revit-addin/install.ps1
    ```

    Revit 開著時，舊版 DLL 會被鎖住。這時加 `-Folder LebrCarbon_5` 之類的新資料夾名稱，重開 Revit 後就會載入新版。

3. 開 Revit 2027。跳出「無法驗證此增益集的發佈者」時，選「永遠載入」。功能區會出現 **LEBR** 頁籤，裡面有「專案設定」、「開始計算」兩個大按鈕，以及「代號 JSON」、「使用說明」兩個小按鈕。
4. 開一個專案，按 **「專案設定」**，第一次會自動在專案中加入 25 個 `LEBR_*` 參數，填完按「儲存」。
5. 填參數：
    - 牆、窗、帷幕嵌板、樓板的「類型性質」填 `LEBR_Code`；外牆本體另填 `LEBR_Code_Body`。
    - 「管理 → 專案資訊」填建築類別、構造、用途和結構參數。
6. 按 **「開始計算」** → 確認計算前檢查 → 結果視窗 → 可「匯出結果 JSON」給網頁。

**不用編譯的安裝方式**：關掉 Revit，雙擊交接包最上層的 **安裝外掛.bat**。它會自動找出電腦上的 Revit 2024～2027，裝好對應的版本。

**不開 Revit 看視窗**：`dotnet run --project revit-addin/Preview -- . shots --interactive`

## 已驗證的事

- **計算引擎**：用手冊附錄三（高雄市 Z 社會住宅）算出 CFR 20.51%、1+ 級，和手冊相同。各項和手冊相差都在 0.05% 以內；差距來自手冊中間值的四捨五入與筆誤。共 74 項自動測試，在 .NET Framework 4.8（Revit 2022～2024）與 .NET 8 都通過。
- **Revit 實測（範例資料）**：按鈕 → 計算前檢查 → 結果視窗，顯示 1+ 級、CFR 20.51%，分頁切換正常。
- **Revit 實測（從模型擷取）**：課程模型複本，填了下表的代號與示範參數後，算出 **1+ 級、CFR 24.60%**、EEC 442,059 kgCO2e，0 個未對應、0 項缺少。

### 測試模型

`測試模型/LEBR_test.rvt` 是課程模型 `NCKU_9hours_intro_course.rvt` 的複本，已執行過「建立參數」。下表的值是用 RevitMCP 寫進去的。最後一次存檔應該有包含這些值，但 Revit 檔無法直接檢查；如果打開後發現沒有，照下表重填即可。

| 類型（Revit） | 參數 | 值 |
|---|---|---|
| 牆 Generic - 150mm、Generic - 200mm（功能都是「室外」） | `LEBR_Code`／`LEBR_Code_Body` | `OW-03`／`CW-00` |
| 帷幕嵌板 System Panel: Glazed | `LEBR_Code` | `CWW-G14-ALPVC` |
| 樓板 Generic Floor - 400mm（Level 1） | `LEBR_Code` | `F-G01` |
| 樓板 Generic Floor - 150mm | `LEBR_Code` | `F-G02` |
| RF 那片樓板（元件 374262） | `LEBR_Exclude` | 勾選 |
| 專案資訊 | `LEBR_WearClass`、`LEBR_Structure`、`LEBR_UseType` | `M`、`RC`、`other` |
| 專案資訊（**示範值，不是真的結構計算書**） | `LEBR_I`、`LEBR_SaD`、`LEBR_Fu`、`LEBR_L`、`LEBR_D0`、`LEBR_Rs` | 1.25、0.6、3.0、250、300、1.0 |

**Revit 2027 以前的版本打不開 `LEBR_test.rvt`。** 改開原始課程模型，按「代號 JSON」→「套用代號」，選 `測試模型_LEBR代號.json`（repo 裡是第1組根目錄的 `測試模型_LEBR代號.json`），上表的值會一次填好。2026-10-25 在 Revit 2027 用原始課程模型實測套用，5 個類型、9 個專案參數、1 個不計入元件全部套上，算出來同樣是 1+ 級、CFR 24.60%、EEC 442,059。

這個模型 Level 2 沒有樓板，所以程式讀到地上 3 層。實際若是 4 層，可在專案資訊填 `LEBR_S` = 4。

## 已知問題與注意事項

1. **資料庫是草稿**（`review_status: draft`），結果視窗會一直顯示提醒。人工核對完成後，把 `scripts/build_json.py` 的 `REVIEW_STATUS` 改成 `reviewed` 再重新產生。
2. **手冊本身有 15 處數字不一致**：資料庫 10 處，見 `README.md`「已知的手冊問題」與核對用 Excel 的「⚠ 需確認」頁；附錄三範例 5 處，見 `lebr-db/計畫書/公式運算邏輯.md` 第三節。都已對照原圖確認不是抽取錯誤，等團隊決定。
3. **`parameters_2025.json` 是手動轉錄的**，不在核對用 Excel 裡，也要對照手冊看一遍（每項都有頁碼）。
4. **屋頂判斷規則的最新修正還沒在 Revit 驗證**。規則是：沒有房間時，模型最高樓層上的樓板視為屋頂板。這版在 `Addins\2027\LebrCarbon_4`。
5. **Revit 外掛資料夾**：`Addins\2027\` 底下有 `LebrCarbon`、`LebrCarbon_2`、`LebrCarbon_3` 三個舊版，Revit 關閉後可刪除；`LebrCarbon.addin` 目前指向 `LebrCarbon_4`。
6. **Snowdon Towers 範例檔（180 MB）在原本那台電腦開啟時 Revit 會卡死**，與外掛無關。測試請用小模型。
7. **外掛沒有數位簽章**，每次換資料夾都會跳安全性提示。
8. **構件代號（例如 `IW-03`、`F-G01`）是草案**，團隊可改，但要同步改 `scripts/extract_lebr_tables.py` 的編號規則與已填過的模型。
9. **不要直接改 CSV 或 JSON**。它們都是程式產生的，要修正的值一律寫進 `corrections.csv`，再執行 `python -I scripts/build_json.py .`。

## 待團隊決定（計畫書第十二章）

| 事項 | 目前做法 |
|---|---|
| 構件代號含不含建築類別 | 類型填不含類別的代號（`IW-03`），外掛依專案類別補成 `IW-M-03` |
| 外牆兩個代號怎麼填 | 兩個參數：`LEBR_Code`（外裝）、`LEBR_Code_Body`（本體） |
| 主結構算法 | 標準公式（式 1～7） |
| 室內地坪怎麼抓 | 目前用樓板類型代號；計畫書建議改用房間面積加房間用途 |
| 手冊不一致採哪個值 | 暫用手冊印的值並標記 `CHECK` |
| 支援的 Revit 版本 | 專案檔設定 2024～2027，只實測過 2027（2024 可編譯） |

## 建議的下一步（依優先順序）

1. 人工核對資料庫與參數表，決定手冊不一致的值，寫進 `corrections.csv`。
2. 組員 3 開始做網頁：先用「匯出結果 JSON」做出等級、四階段、七類構件三張圖。
3. 在一個真實專案模型上完整試一次，重點確認面積定義（外牆是否扣開口、地坪面層）。
4. 做「專案設定」表單，取代手動到專案資訊填參數。
5. 數量擷取補上：房間用途排除、f3 出挑、窗族群寬高參數的例外處理。
