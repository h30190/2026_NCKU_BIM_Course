## PowerShell 啟動時的紅字與中文亂碼

- `profile.ps1` 的 PSSecurityException 是 PowerShell 個人設定檔被執行原則阻擋；應分別確認後端是否啟動。
- 單次執行可信任的腳本可使用 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-backend.ps1`，不需永久放寬整台電腦設定。
- 中文亂碼可能是終端機輸出編碼或 Windows PowerShell 對無 BOM UTF-8 腳本的讀取問題。本次交件的 PS1 使用 UTF-8 BOM；若只有外部程式輸出亂碼，再檢查終端機 UTF-8 設定。
- PowerShell 5.1 的 Add-Type 使用較舊 C# 編譯器，曾因獨立材質判斷類別的 `=>` 方法語法失敗；已改成傳統方法區塊，並以 Windows PowerShell 5.1 實際執行 `build.ps1 -Test` 全程通過。
- 啟動腳本透過 Start-Process 在背景執行；關閉呼叫它的終端機不等同停止服務。依 PID／工作管理員確認實際後端狀態。

## 配對失敗：外部出入口／Exterior

舊版直接比較文字，讓語意相同的 `外部出入口` 與 `Exterior` 被判為不同用途。新版僅在比對時把 `外部出入口、外部、室外、Exterior` 正規化為 Exterior，不改寫護照原始值。其他不在別名表內的用途保持原判斷。

## 替換按鈕未執行

Matched 還不是已預留。必須先按「預覽並預留」，狀態由 Available 變成 Reserved，才能執行 B-1 替換。

### 重複預留與配置修正

舊版允許相同狀態的請求覆寫目標，曾在隔離測試中重現同一護照被另一位操作者預留及改綁另一扇門。新版把預留綁定操作者與目標模型／Element ID／UniqueId，PATCH 需要 `expectedRevision`，使用資料庫條件式更新，並將配置與稽核寫入同一交易。

修正後獨立 API 驗證結果為：第一次預留 HTTP 200、另一位操作者再次預留 HTTP 409、原操作者配置 HTTP 200、不同目標再次配置 HTTP 409，最終目標仍保持原門。並行預留測試連跑 10 次均只有一個成功者。測試另涵蓋過期版本、同目標外觀修復、取消預留、舊配置升級、零庫存及稽核失敗時回復交易。

修正版 Go 測試共 87 個通過事件（包含子案例），0 個失敗；Windows PowerShell 5.1 完整 `build.ps1 -Test`、19 項材質判斷、隔離卸載驗證與 Revit 2024 編譯皆通過。

外掛在動 Revit 前再次確認預留與版本；工作流程送出期間阻擋重複點選。這些是本機工作流程一致性檢查，操作者字串與本機標記不構成跨網路的帳號驗證。

### 解除安裝修正

舊卸載腳本未處理新版 `TemporalBimReleases`。新版會在版本資料夾範圍內把本外掛檔案移至可回復備份，檢查 manifest 的 AddInId，拒絕錯誤路徑與接合點；測試確認 WhatIf 不更動檔案、部署檔可回復且其他外掛保留。所有卸載測試只使用暫存的假安裝資料夾。

## 類型已變但外觀看起來相同

舊版僅複製 B 模型既有類型、套用寬高及備註，因此名稱變成 `GP_GP-D-…`，卻仍是原門造型。

新版依來源模型與 UniqueId 匯出 A 模型門族群，以獨立族群名稱載入 B。若護照記載白色門扇，即使來源範例門板仍為 Wood - Birch，也將獨立白色表面材質套用至門板。白色以 RGB 245/245/245 作視覺呈現，不表示材料性能已獲驗證。

替換交易檢查宿主、位置、方向與尺寸；載入失敗或 Revit 錯誤即回復。舊版 Allocated 門可透過「更新已配置門」更新，無須重新占用護照。確認外觀應在 3D 著色／擬真視圖進行，黑白平面圖不一定顯示材質差異。
