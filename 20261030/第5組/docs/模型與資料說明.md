# 模型與資料說明

本次提交不含 RVT、工作資料庫、執行檔或個人電腦備份。RVT 由組內共享資料夾取得；本文件不虛構尚未提供的公開下載連結。

## 模型需求

- 來源：A 模型，含可匯出的門族群、實體與類型參數。
- 目標：B 模型，含待替換的門與宿主牆。
- 擷取及替換使用相同的 A 模型；不要重新建一份只有相同名稱但不同 UniqueId 的 A 模型。
- A、B 模型在同一個 Revit 2024 同時開啟，不要同時開啟多份同名來源模型。
- 來源族群不可為就地族群，且來源／目標的宿主方式必須相容。

示範使用的模型檔名為 `A模型_綠色護照來源.rvt`、`B模型_新建案.rvt`。檔名本身不構成資料連結；護照保存的來源模型與 UniqueId 才是定位依據。

## 從頭重測

1. 將 A、B 原始模型複製到新的測試資料夾，保留原始檔；測試成果若要保存，另存副本。
2. 準備另一份本專案的後端工作資料夾，勿複製舊 `backend/data` 或 `backend/logs`。
3. 先停止舊後端，再從新資料夾啟動 `start-backend.ps1`。外掛固定使用 127.0.0.1:8080，因此一次只能連一份後端。
4. 確認圖台顯示 0 筆，再重新擷取、審核、配對及替換。

原有 Allocated／Reserved 不會因重新開啟 RVT 就自動清除。重新測試時採獨立空白資料庫，不直接覆寫舊成果。

## 交付與可追溯性

本機 SQLite 包含模型參數快照、審核說明及配置紀錄；不以 Git 反覆合併工作資料庫。需要分享範例資料時，先匯出已檢查的 JSON／CSV，再由組內確認後另行提交。

使用者模型、來源圖片與實際操作紀錄沒有隨本次程式碼公開。來源門仍須存在於 A 模型，才能重現族群載入及外觀替換。
