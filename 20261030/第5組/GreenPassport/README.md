# NCKU Green Passport｜Revit 門構件循環再利用外掛

本專案由既有 `BIM_Plugin` 改作為門構件再利用應用。操作權責如下：

```text
A 模型（Revit）
  └─ 完整擷取實體＋類型參數 → 人工檢核 → Approved 才成為供應
                                             │
B 模型（Revit）                              │
  └─ 設計者確認八項需求 → 三態配對 → 預留 → B-1 Transaction 替換與稽核
                                             │
                                             └─ 同一份 SQLite 資料庫
                                                        │
                                               網頁圖台（嚴格唯讀）
```

網頁不提供人工審核、需求配對、預留、資料修改或 Revit 模型操作；這些動作只在 Revit 外掛中完成。

## 功能

防火時效、性能、需求、證明等欄位已退役，A／B／圖台不再顯示、編輯或作為審核及配對依據。舊 SQLite 欄位與 RVT 原文留作歷史相容，API 與參數查閱會排除退役欄位。

- A 模型批次擷取所有門。
- 完整保存每扇門的 Revit 實體參數與類型參數；未對應欄位仍可查閱。
- 核心欄位記錄來源：BIM、COBie、人工或 unknown，並保留單位、定義與映射警告。
- 門扇厚可讀取 Revit「厚度／Thickness」（包含門族使用的 `WINDOW_THICKNESS`）。已建檔的空白厚度會由保存的原始毫米參數帶入；保留人工值，門框深度不作為門扇厚度。
- 開啟審核時，舊護照的空白核心欄位會從已保存的完整 Revit 原始參數重新映射（優先 GP、標準 Revit、再到 COBie）；既有人工值不覆蓋，回填值仍須人工檢核後才可通過。
- 人工檢核狀態：`Pending`、`Approved`、`Repair Required`、`Rejected`。
- 審核結果以中文呈現：待審核、已通過審核、需修復、未通過審核；已通過項目以綠色標示。個別／批次審核成功後重新載入清單，網頁切回前景時更新狀態。
- A 頁面只擷取、補填模型資料與建立待審核護照；「新建」只供尚未建檔的門勾選，既有項目保留灰色停用勾選框並明確標為「已建檔」，審核結果為唯讀。已建檔項目讀取平台保存的資料與狀態，避免重複建檔或重開後誤顯示待審核。
- 個別及批次審核的說明若尚無既有內容，介面預設填入「條件符合」，仍可由檢核人依實際狀況修改。
- A 建檔流程：未建檔 → 勾選 → 按「建立所選護照」→ 後端儲存成功才在原清單顯示「已建檔／待審核」。失敗項目保留勾選以便重試；單純讀取模型或勾選不會新增護照。
- 所有審核集中到「護照清單與審核管理」：提供「審核選取項目」、每列「審核此項」及「全部通過審核」。批次操作填檢核人與說明，逐筆顯示缺漏原因，只核准完整的 Pending 項目；結果直接儲存並重新載入清單。
- 只有 `Approved + Available + quantity > 0` 會進入 B 模型候選供應。
- B 模型由設計者逐門確認寬、高、尺寸定義、門扇厚、開啟方式、方向、用途、材質、淨寬與安裝條件。
- A、B 操作介面以淡黃色標示八項必填核心資料；空白時改為淡紅色。門寬、門高、門扇厚度、開啟方式、開門方向、室內外用途、材質、有效通行淨寬未完成時，不得 Approved／Matched。
- B 模型的門寬、門高固定以 ±5 mm 配對，前後端皆不可放寬。配對結果會顯示 A 模型 Family／Type 預覽圖；舊護照沒有圖片時自動產生帶尺寸的門示意圖，點圖或雙擊結果列可放大。
- B 專用參數對應優先讀取 `B_`／`需求_`／`GP_B_` 需求欄位，再讀 GP、Revit 標準與 COBie 值；材質的 ElementId 會解析成名稱，宿主牆厚由 Wall.Width 帶入。空白需求維持待確認。
- B 視窗提供「查看 B 參數與來源」、欄位來源提示及「確認名稱建議」。雙開／室內外名稱等推論需先確認才套用；名稱與模型功能衝突、通用材料名稱及缺少淨寬／方向都會列在映射警告。下拉選項提供目前核准供應的開啟方式、方向及材質，仍可自行輸入。修改需求會清除過期配對結果。
- B 模型只以紅色＊欄位判定配對：門寬、門高、門扇厚度、開啟方式、開門方向、室內外用途、材質、有效通行淨寬。有效通行淨寬採 A ≥ B 最低需求。尺寸定義、門扇數、安裝檢查、需求依據、保存狀況等只顯示／記錄，不影響配對結果或排序。
- 已移除「證明已核對」勾選欄位及相關審核／配對門檻；證明編號為選填。舊資料的核對旗標僅留存供相容使用，不影響結果。
- 配對結果為 `Matched`、`Pending Review`、`Not Matched`；缺資料不會被當成通過。
- B-1 替換包在 Revit Transaction；記錄護照、來源／目標 UniqueId、替換前／後 TypeId、操作者與原因。

## 啟動

### 後端與唯讀圖台

首次使用先在此資料夾執行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1`，產生後端與外掛；本倉庫不提交編譯產物。

```powershell
.\start-backend.ps1
```

- API：`http://127.0.0.1:8080`
- 唯讀圖台：`http://127.0.0.1:8080/dashboard`
- SQLite：`backend/data/temporalbim.db`

### 建置與安裝 Revit 2024 外掛

```powershell
cd revit-plugin
dotnet build .\TemporalBim.csproj -c Release.R24
.\install.ps1 -Version 2024
```

重新啟動 Revit 2024 後會看到 `Green Passport` 分頁：

1. `A｜擷取與建立護照`：在 A 模型保存資料並進行初次人工檢核。
2. `B｜確認需求、配對與替換`：在 B 模型先選一扇門，再確認需求、配對、預留與替換。
3. `護照清單與人工檢核`：查看完整資料／來源，或更新人工檢核資格。
4. `開啟唯讀護照圖台`：只瀏覽同一份資料庫。
5. `更新已配置門｜族群與材質`：更新與目前模型／Element ID 對應的 Allocated 門。

## 驗證

```powershell
.\scripts\regression.ps1
.\scripts\smoke.ps1
```

回歸測試涵蓋：完整匹配、尺寸不符、淨寬的最低需求邊界、淨寬未知、已退役的防火欄位不影響審核與配對、Approved 驗證，以及網頁寫入遭拒。冒煙測試檢查健康端點、護照清單、圖台與唯讀邊界。

## 重要限制

- 模型參數是資料宣告，不等於實體量測、法規判定或性能證明。
- 淨寬缺漏時維持 `待確認`，不以名義門寬代替。
- 替換需在同一 Revit 同時開啟護照來源 A 模型。依來源模型與 UniqueId 定位門，匯出獨立命名的族群再載入 B，保留來源幾何、類型及材質；無法確認來源或宿主不相容時明確停止，不再只改原門名稱。
- 護照指定「白色」門扇時，建立獨立的白色表面材質並指定到門板參數；門框與把手維持來源材質。此為依護照文字呈現的材質外觀，並非實體材質檢測。無指定顏色時保留來源外觀，不推測色彩／紋理。
- 舊版已配置的門可選取後使用「更新已配置門｜族群與材質」。只接受 Allocated 且目標模型／Element ID 相符的護照，維持已配置狀態並補登前後 TypeId 稽核。請在 3D「著色／擬真」檢視材質；黑白平面圖未必有變化。
- 外掛不會自動另存 RVT；請在完整配置後由使用者另存 B-1 版本。
- 後端更新失敗但 Revit Transaction 已完成時，護照會保留 `Reserved`，畫面會要求先補登稽核，不應重複替換。

## 主要檔案

- `backend/handlers_passports.go`：建檔、人工檢核、三態配對與供應生命週期。
- `backend/db.go`：SQLite schema 與增量 migration。
- `backend/static/dashboard.html`：唯讀圖台。
- `revit-plugin/DoorDataExtractor.cs`：完整參數快照與決定性欄位映射。
- `revit-plugin/PassportCandidateForm.cs`：A 模型批次確認。
- `revit-plugin/PassportReviewForm.cs`：後續人工檢核。
- `revit-plugin/DemandMatchForm.cs`：B 模型需求確認、配對、預留與 B-1 替換。
- `revit-plugin/DoorSwapHelper.cs`：Revit Transaction 與替換稽核資訊。
