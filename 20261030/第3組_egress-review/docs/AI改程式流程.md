# 用 AI 改程式：只統一四件事

內容、做法、用哪個 AI、提示詞怎麼寫，**都自由**。
只有下面四件事大家要一樣，因為不一樣的話，合併時會壞掉。

## 1. 開工前拉最新版

```
git pull origin team
```

## 2. 讓 AI 知道整合規則

開始改之前，跟 AI 說一句（其他怎麼講都可以）：

```
請先讀 docs/整合規則.md，改的時候不要違反裡面的規則。
```

使用 Claude Code 或 Codex 時，它會自動讀 `AGENTS.md`，裡面已經寫了這句，不說也可以。

## 3. commit 前跑檢查

```
node check.js B          （B 換成你的角色，也可以不加）
```

- **失敗**：會造成 bug，要修好才能 commit。把訊息貼給 AI 請它修。
- **提醒**：不會造成 bug，看一下就好。例如你改到了別人主要負責的檔案。

`[ ]` 裡的數字對應 `docs/整合規則.md` 的條目，可以直接查。

## 4. 只 commit 自己改的檔案

```
git add engine/geometry.js
git commit -m "B: 加入候選出口距離"
git push
```

不要用 `git add .`，以免把自動產生的檔案或 `.rvt` 一起加進去。commit 訊息開頭寫你的角色，其他自由。
