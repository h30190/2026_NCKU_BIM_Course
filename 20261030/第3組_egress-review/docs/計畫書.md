# Revit 逃生動線法規檢討系統｜產品與技術計畫

版本：0.1（規劃稿）  
日期：2026-10-19  
目標：在既有 Revit MCP 與 RFI 前端工作流程旁，建立可追溯、可重算的逃生動線檢討工具。第一階段以本機使用為主，先完成模型資料擷取、規則化計算與圖面呈現，再擴充多人協作和正式報告。

## 1. 設計原則

1. **模型提供幾何與屬性，程式負責所有計算。** Revit API／外掛讀取模型；後端幾何與規則引擎以明確程式碼產生距離、路徑、寬度、轉折與判定。語言模型不得計算、判定合規、推測模型幾何或自行生成法規門檻。
2. **每項結果都能追溯。** 顯示模型版本、樓層／居室、使用類組、適用條文與版本、計算參數、路徑圖、結果及資料缺漏。規則或模型更新後另建檢討批次，不覆寫舊結果。
3. **把法規判定和設計風險提示分開。** 法規條文有明確門檻時才產生法規符合／不符合；轉角風險、保守餘裕等自訂檢查要標成「設計提示／專案標準」，不得偽裝成法定門檻。
4. **不完整資料不等於不合格。** 無法辨識房間封閉邊界、門、樓梯或用途時，標記「待補模型資料／待人工確認」，說清楚缺少什麼。
5. **工具是檢討輔助，不代替建築師簽證或主管機關認定。** 適用法規、核定用途、例外條款和地方要求由專業人員確認。

## 2. 使用流程

1. 使用者在 Revit 開啟建築模型，選擇專案、樓層／階段與要檢討的模型範圍，執行「擷取／同步」。
2. 外掛檢查模型可用性，將房間／空間、邊界、門、走廊、樓梯、出口、樓層、面積及必要參數送到本機 API。擷取只讀取模型，不改動 BIM 元件。
3. 使用者在專案設定中手動選擇建築類別與使用類組（A～I 類及細組），並確認用途、樓層、地下層、樓高、防火構造、核定用途、適用版本等條件。系統可提供選項說明，不可僅憑房間名稱自行定類。
4. 系統逐居室檢核資料品質，列出待確認項目。使用者修正 Revit 或在授權範圍內補上明確的檢討屬性後，重新擷取。
5. 使用者選取法規規則包與專案保守設定，按「執行檢討」。後端以固定版本規則引擎計算，不呼叫語言模型。
6. 結果依樓層／居室以卡片與表格呈現；點入居室即可查看平面、逃生路徑、量測值、轉折風險與法規依據。
7. 使用者複核警示、標註人工確認事項，鎖定檢討批次；後續再用同一批次資料產生 PDF／計畫書頁面。

## 3. 系統分層與資料契約

### Revit 端（C# Revit API 外掛，MCP 可作為操作入口）

- MCP 負責觸發「取得模型資訊、檢查模型、擷取、定位／顯示檢討結果」等工具操作；MCP 是控制／協調介面，不是幾何運算器。
- 外掛以 Revit API 讀取 Room／Space、邊界曲線、房間用途參數、Door、牆、樓板、樓梯、扶手／平台（若模型可辨識）、樓層、視圖、Phase、Design Option、單位與模型座標。
- 匯出標準化 JSON，至少包含穩定 element id、UniqueId、類別、樓層、座標系／單位、幾何、寬度與高度來源、房間相鄰關係、擷取時間、模型識別碼及資料品質警告。
- 對無法從模型可靠判定的資料（例如門是否可作為法定出口、某門是否常閉、防火時效、核定用途）設為待確認欄位，不從外觀猜測。

### 本機後端（Go API + SQLite 起步）

- API 接收模型快照、管理專案／規則包／檢討批次、執行確定性計算、回傳結果與路徑幾何。
- SQLite 適合單機原型；多人同時登入或多機共享前改用 PostgreSQL，並加入帳號、組織／專案成員、角色權限、稽核紀錄及備份策略。SQLite 不應放在多人共用網路磁碟作為正式並行資料庫。
- 計算服務採版本化純函式：相同模型快照、同一規則版本與參數必須得到相同結果；記錄輸入雜湊、程式版本及規則版本。

### 前端（既有 RFI UI 延伸）

- 以建築檢討工作區呈現專案、樓層、居室、檢討批次、結果與人工複核狀態。
- 使用者登入／多人權限與檢討功能分層實作，不讓前端隱藏按鈕充當真正的權限控制；每個 API 操作都由後端驗權。

## 4. 法規設定與檢核範圍

### 規則包

建立「法規規則登錄表」，每條規則包含：唯一編號、法規名稱／條次／款目、官方來源、版本生效日期、適用條件、輸入欄位、計算式或比對方式、例外／排除條件、輸出訊息、測試案例、審查者及核准日期。每個檢討批次固定使用一份已核准規則包；法規更新先由專業人員審閱、建立新版本、跑回歸案例，再啟用。

### 第一階段建議範圍

- 依樓層／建築物使用類組及其他明確條件判斷哪些逃生檢討規則適用；把需要的條件以表單問清楚。
- 房間沿可通行空間至出口／直通樓梯的行走距離；依條文要求以可行路徑，不以兩點直線距離替代。輸出路徑、距離、門檻、起終點定義及中間經過空間。
- 多方向／多座直通樓梯的路徑可達性，以及依法規定義的共同路段長度（僅在模型拓樸、出口身分與適用條件已確認時啟用）。
- 門、走廊、樓梯等寬度的幾何量測與條文門檻比較；模型未標示有效淨寬、防火門屬性或量測定義時，要求確認，不以族群名義推測。
- 結果分為「符合」、「不符合」、「需人工確認」、「模型資料不足」；另有「保守提示」層。

官方法規起始來源包括《建築技術規則建築設計施工編》（例如防火避難設施相關條文）、《建築技術規則總則編》與《建築物使用類組及變更使用辦法》。需依專案用途擴充《建築技術規則建築設備編》、《各類場所消防安全設備設置標準》及其他適用規定。法規條次、例外與適用性應由建築師／法規顧問逐項核定後，才能作為正式自動判定依據。

### 轉折角與保守檢核（特別需求）

- 將角度／轉折風險做成專案可調參數，例如「路徑轉折角下限」、「牆面淨空餘裕」、「門扇／轉角掃掠範圍」。UI 顯示目前值、單位、設定者、設定日期與理由。
- 程式從路徑中心線切線計算轉向角，並用轉角兩側牆面／門洞／通道淨寬幾何檢查實際可通行空間；結果標出轉角位置、角度、淨空與觸發的專案門檻。
- 除非已確認某項角度門檻直接出自適用法規，否則只列「專案保守檢核／需複核」，不列法規違規。角度和淨空是兩種不同問題，建議同時呈現，不用一個角度值取代全部轉角安全判斷。
- 以參數情境比較顯示「法規基準」和「專案保守值」的差異，讓設計者看出降低門檻或提高餘裕造成的影響。數值由專業團隊訂定，計畫不預先杜撰法定角度。

## 5. UI 建議

### 專案總覽

- 上方：專案、模型版本／擷取時間、規則包版本、檢討樓層、建築類別／使用類組選擇、執行檢討與匯出。
- 指標卡：符合、不符合、待人工確認、模型資料不足；以數量和比例呈現，點擊可篩選對應居室。
- 樓層卡片：每層居室數、主要出口／樓梯、未檢項數、最長路徑、警示數。

### 居室圖塊

每張卡片放置：房間名稱／編號、樓層、使用類組、狀態徽章、到目標出口的路徑距離／適用上限、候選出口數、最需注意轉角數、資料缺漏提示。卡片點擊開啟詳細檢討，不把過多法規文字塞進卡面。

### 平面檢討畫布

- 顯示 Revit 平面幾何或經外掛擷取的向量線；含比例尺、北向、樓層、圖例與模型版本。
- 可切換圖層：房間／牆、門與開啟方向、走廊、樓梯、出口、逃生路徑、替代路徑、轉角／淨空風險、量測尺寸。
- 路徑以方向箭頭和起終點符號呈現；不同出口使用不同線型／顏色；不符合處用標記編號連到右側明細，避免只靠紅綠顏色傳達。
- 點選房間、路徑或轉角，可同步顯示來源 Revit 元件、量測值、規則條文、計算參數和人工確認狀態。支援「法規門檻／專案保守值」切換。

### 審查明細與計畫書

- 每條發現列出：結果、條文及版本、事實輸入、演算法／計算結果、路徑圖、模型元件連結、資料品質、人工覆核欄與處置紀錄。
- 後續報告模板可包含封面與專案資料、法規適用表、模型／規則版本、樓層總圖、居室路徑圖、逐室結果矩陣、保守風險清單、待確認事項及簽核欄。
- PDF／報告由固定版型和程式化圖表產生；圖面、數值與表格取自鎖定的檢討批次，不由語言模型改寫結果。

## 6. 多人登入與權限（規劃）

第一階段本機單人可先用本機工作階段；第二階段加入帳號與專案成員制。建議角色：系統管理員（使用者／規則包設定）、專案管理員（成員與專案設定）、檢討工程師（擷取、設定、執行）、審查者（覆核／退回）、檢視者（唯讀）。權限拆成「專案讀取、模型擷取、規則設定、執行檢討、人工覆核、匯出報告、成員管理、規則發布」。所有授權在 Go API 端檢查，寫入稽核紀錄；使用安全密碼雜湊、工作階段／短效憑證、登入節流、備份和帳號停用機制。正式多人使用採 PostgreSQL；規則發布與人工覆核保留操作者和時間戳記。

## 7. 建議分期

| 階段 | 交付內容 | 完成條件 |
|---|---|---|
| 0. 法規與模型盤點 | 確定首批用途類組、樓層條件、檢討條文；盤點實際 Revit 版本、房間／門／樓梯建模習慣 | 法規專業人員核可首批規則清單；列出必填與待人工確認欄位 |
| 1. Revit 擷取原型 | Revit API 擷取指定樓層房間、邊界、門、樓梯、出口與模型品質報告 | 同一模型重複擷取識別一致；資料缺漏能指出對應元件 |
| 2. 幾何與路徑引擎 | 建立可通行圖、距離／候選出口計算、轉角角度與淨空量測 | 以人工核算案例比對；相同輸入重算一致；無路徑／斷圖能解釋 |
| 3. 首批法規規則 | 將核准條文轉成版本化規則和邊界案例 | 每條規則都有測試案例、來源與審核紀錄；待確認不被判成通過 |
| 4. UI 與平面呈現 | 專案總覽、居室卡、篩選、平面圖層、路徑和轉角明細 | 從專案總覽可追到逐室圖面及計算依據；資料不足可直接定位 |
| 5. 報告與協作 | PDF 模板、登入、專案角色、審查流程、稽核與資料庫升級 | 不同角色 API 權限測試通過；報告可回溯到模型與規則快照 |

## 8. 技術風險與處理

- **Revit 模型建置差異：** 房間邊界、門淨寬、出口用途未必完整；先建立資料品質檢查與建模指引。
- **幾何拓樸錯誤：** 門洞可能未連接空間、牆線小縫造成錯路；將拓樸修補保持可見、可配置、可稽核，禁止默默改模型。
- **法規版本與例外：** 規則有修法日期和適用條件；規則包需專業審核、版本鎖定與回歸案例。
- **路徑不是單純最短路徑：** 應使用可行通道圖並明確定義量測規則；含樓梯的跨樓層路徑另列為擴充項，不能只靠平面圖推導垂直移動。
- **視覺誤讀：** 顏色需搭配圖示、文字與線型；印出灰階仍可辨識。
- **多人資料安全：** 前端藏控件不足以授權；需 API 層驗權、操作稽核、備份與資料遷移策略。

## 9. 建議補充的呈現方式

1. **把「符合」和「可信度／資料完整度」分開。** 顯示法規結果，同時顯示模型資料完整度，避免模型缺資料時誤呈綠色通過。
2. **增加路徑情境比較。** 同房間顯示最近可用出口、法規指定的替代出口／共同路段，以及專案保守設定下的風險變化。
3. **提供模型修正清單。** 按 Revit 元件列出缺少的房間用途、門有效淨寬、樓梯終點或出口確認，附定位／選取按鈕。
4. **加入模型變更差異。** 新模型與上一版比較新增／刪除房間、路徑長度變化、狀態轉變與新增警示。
5. **區分事實、規則、建議。** 每個檢查卡用不同區塊呈現模型量測、法規判定、保守提示和人工結論。
6. **為每張圖保留可列印資訊。** 比例尺、方向、圖例、樓層、模型版本、規則包版本、批次編號及日期應與報告一致。

## 11. 第一輪決策建議

先用一個具代表性的 Revit 樓層和一種使用類組做垂直切片：擷取房間／門／走廊／樓梯 → 資料缺漏清單 → 單樓層逃生路徑 → 一至兩項經核定的法規規則 → 平面圖卡與逐室明細。待這條流程可重現、可核算後，再增加跨樓層、更多用途類組、多人登入和 PDF 計畫書。轉角保守值先以「專案設定」方式呈現，由你和法規顧問選定，不預設為法定值。
